# 首款商业 3D 游戏：产品与平台策略

> 状态：**方向草案 v0.2**。建立于 2026-09-01，用于决定首款真实商业游戏“先做什么、先在哪个平台证明、用什么证据继续投入”。它是可证伪的产品假设，不是已经承诺的发布日期、销量或全平台支持范围。

## 1. 执行摘要

当前建议是：

1. **Steam / Windows 首发**，采用一次性付费的单机产品；先建立愿望单、Demo、Playtest 和可构建交付闭环。
2. 做一款**风格化俯视角 3D 紧凑型沙盒**，而不是开放世界、多人在线或纯框架 Showcase。
3. 领跑概念暂名 **《游牧工坊》（Nomad Workshop）**：玩家驾驶一座移动的微型工坊，在“探索与回收 → 布置生产 → 抵御风暴 → 带着成果迁徙”的循环中成长。
4. Android / iOS 保留输入、UI、性能和存档层面的可移植性，但**垂直切片成立前不同时开发移动产品**；届时再通过独立 Gate 判断是移植、重新设计，还是放弃。
5. 游戏首先对玩家和市场负责。它会真实使用 SSFramework 并反向暴露缺口，但不能为了展示 Framework、AI 或生成工具而牺牲玩法、审美和范围控制。

一句话产品承诺：

> **把荒野里捡回的一堆废料，亲手布置成一座会运转、会抵抗风暴、还能陪你继续上路的微型家园。**

## 2. 决策分层

| 层级 | 当前内容 | 变更方式 |
|---|---|---|
| 已接受方向 | 正规商业游戏；3D；单人优先；同仓独立业务程序集；先证明核心循环 | 只有新证据表明目标不可行时调整 |
| 当前推荐 | Steam / Windows 首发；风格化俯视角；付费单机；紧凑型沙盒 | 完成概念与灰盒 Gate 后确认 |
| 领跑假设 | 《游牧工坊》；探索、生产布局、风暴防守、迁徙四段循环 | 与备选概念做同标准对比，不靠偏好直接锁定 |
| 有意延后 | Android / iOS、Steam Deck 完整认证、主机、多人、UGC、LiveOps、运行时生成式 AI | 只有核心产品和资源条件触发时进入排期 |

这能避免两种相反风险：既不把新游戏降格为一次性的技术 Demo，也不在第一个原型前背上开放世界、多平台和长线运营的全部成本。

## 3. 目标玩家与产品支柱

### 3.1 初始目标玩家

优先面向喜欢以下体验的 Steam 玩家：

- 喜欢基地构筑、资源链、空间布局和“看着系统运转起来”的满足感；
- 希望有直接操控、探索与危险，而不只是长时间看表格；
- 能接受 20–60 分钟一段的 PvE 游戏节奏，并愿意为了不同布局或路线重玩；
- 喜欢风格化、可读性强、有温度的微缩世界，不要求写实 AAA 画面。

竞品只用于拆解受众、表达和风险，不等于拼装玩法。第一轮可研究 `Dome Keeper`、`Thronefall`、`The Wandering Village`、`Against the Storm`、`Wall World` 等产品在核心幻想、单局结构、视觉可读性和商店表达上的做法；正式立项前再按当时市场数据建立同平台、同价位、同团队规模的可比集。

### 3.2 四个产品支柱

1. **基地就是主角**：玩家不是只升级菜单数值，而是在一个可见、可触摸、可破坏的 3D 工坊上安排设备、路径和防御。
2. **准备与兑现相互验证**：白天的探索和布局，会在风暴来临时直接产生可见后果；防守不是另一款小游戏。
3. **小地图承载系统深度**：用组合、空间与规则产生复玩，不靠无限地图和海量手工内容假装规模。
4. **十秒可读的风格化表达**：轮廓、颜色、动画、特效和音效首先服务状态可读性，同时形成适合截图与短视频传播的辨识度。

### 3.3 明确非目标

首个商业证明阶段不做：

- 无缝开放世界或程序化大世界；
- 联机合作、PVP、服务器权威或账号系统；
- 角色创建器、大量过场、全语音或分支长篇叙事；
- 无限科技树、复杂物流网络和几十小时内容；
- 为展示 AI 而让玩家在运行时直接生成内容；
- PC 与移动端同时设计、同时首发。

## 4. 平台策略

### 4.1 平台顺序

| 平台 | 当前角色 | 为什么 | 进入条件 |
|---|---|---|---|
| **Steam / Windows** | 首发目标 | 适合付费单机、键鼠与手柄；有公开商店页、愿望单、Demo、Playtest 和 Next Fest 反馈路径；当前开发机可直接构建验证 | 概念 Gate 通过后建立 Windows Build Profile 与可分发 Player 包 smoke |
| **Steam Deck** | 次级兼容目标 | 与 Steam 首发路径接近，也能倒逼手柄、字号、帧率和暂停语义 | 垂直切片键鼠/手柄均成立后，用真实设备或可靠测试环境验证；不提前承诺认证 |
| **Google Play / Android** | 后续可行性分支 | Unity 工具链可用，但触控、设备碎片、温控、包体、商店测试和商业模式会改变产品 | 垂直切片后通过移动 Gate，再安装固定 Android 工具链并建立真机矩阵 |
| **App Store / iOS** | 后续可行性分支 | 高价值设备生态，但本地最终构建需要 Xcode / macOS，且有开发者会员、签名、审核和设备验证成本 | Android 或独立移动产品假设先成立；具备 Mac / Xcode 或稳定云构建与真机 |
| 主机 | Later | 认证、开发套件、平台 SDK 和支持成本均更高 | PC 商业证据、资源与发行合作成立后另立项目 |

### 4.2 为什么不同时做 PC 和手机

“Unity 可以切平台”只解决了部分编译问题，不能自动解决：

- 直接操控、建造和镜头在触控上的信息密度；
- 移动场景常见的短时、可中断会话，与本项目假设的 20–60 分钟 PC 单局之间的节奏差异；
- 不同宽高比、安全区、字号、虚拟摇杆与手柄路径；
- 中低端 GPU、内存、热降频、安装包和后台生命周期；
- 付费单机与 IAP / 广告 / 长线留存之间完全不同的产品设计和获客模型；
- iOS 的 Xcode / macOS 构建链，以及两家商店各自的账号、测试、隐私和审核要求。

因此采用“**产品单平台，架构可移植**”：业务核心不依赖 Steam API；输入使用 Action 层；UI 避免写死分辨率；存档和平台服务藏在接缝后；性能预算从第一天记录。但在移动 Gate 前，不制作虚拟摇杆、不接广告 / IAP SDK，也不维护第二套产品 UI。

### 4.3 移动 Gate

只有以下问题都有正面证据，才把 Android / iOS 从 Later 提升到正式目标：

1. 直接操控、镜头和建造在 6–7 英寸触屏上无需遮住核心画面；
2. 一次自然游戏段可压缩到约 10–20 分钟，暂停和恢复可靠；
3. 代表性中端 Android 与目标 iPhone / iPad 达到约定帧率、温度、内存和包体预算；
4. 玩家愿意接受明确的移动商业模式，且它不破坏 PC 产品承诺；
5. 团队能承担真机矩阵、商店合规、客服和更新维护。

## 5. 当前市场信号如何影响选型

这些数据只能帮助提出假设，不能预测本游戏收入：

- Steam 的付费游戏市场很大，但收入极度集中。We Love It 对约十万款有价格且有评论的游戏做的估算中，生命周期收入中位数约为 3,552 美元，前 1% 占约 84.6%；其方法基于评论数与当前标价推算，明确不包含 DLC、区域价格和真实折扣，因此只适合看整体分布与相对信号。
- 同一份 2026 报告显示 Sandbox 在中位数、头部收益和“超过 10 万美元”的估算命中率上表现突出。这不是让项目做大世界的理由；恰恰说明应争取**玩家可组合、可拥有、可反复讲故事的沙盒感**，同时用微缩空间和单局结构限制生产成本。
- Valve 的官方路径允许商店页尽早收集愿望单，Demo 可触达已有愿望单玩家；Steam Next Fest 专门用于未发行游戏的可玩 Demo、玩家反馈和曝光。游戏必须在核心循环有说服力后尽早进入“能被外部玩家理解和试玩”的状态，而不是开发结束才营销。
- Sensor Tower 的 2026 报告称，2025 年移动游戏产生约 820 亿美元 IAP 收入，Steam 产生约 120 亿美元付费游戏收入。两项口径并不相同，恰好说明两个市场都重要、商业结构却不能混为一谈，不能把同一设计无成本复制过去。

结论不是追逐某个热门标签，而是选择一个同时满足“玩家幻想强、十秒可表达、系统能复玩、内容成本可控”的交集，并在投入大量美术前用真实玩家和商店表达验证。

### A. 游牧工坊（当前领跑）

一句话感受：**像把一辆荒野房车、一张会运转的自动化桌游和一次沙尘暴求生压进同一个微缩场景。**

**玩家看到什么：** 斜俯视镜头下，一台四足或履带式工坊停在荒凉盆地中央。甲板只有几十个格子，橙黄舱灯、铜管和帆布让它像一个温暖的小家；远处的紫灰风墙、闪电和被吹弯的草木则不断提醒玩家这里并不安全。玩家直接操控一名回收工程师跑下甲板，在近处废墟、断裂风机和沉没货柜间寻找材料，工坊始终在画面或回程路径上，既是基地也是最需要保护的“角色”。

**实际怎么玩：** 每次停靠先观察 3–5 个兴趣点和即将到来的天气，再决定冒险路线。玩家亲自拾取或让小型无人机拖回废料，把它们加工成板材、电池和密封剂，然后在有限甲板上摆放设备。设备不是单纯加数值：熔炉会产热和噪声，蓄电池怕雷击，冷凝器放在边缘产水更快却更容易损坏，防风板会保护后方也可能堵住维修通道。风暴来临后游戏仍保持直接操控，玩家要搬运电芯、扑灭故障、临时转接线路、启动炮塔或用牵引钩改变敌人路线；此前的布局会在眼前逐项兑现。

**关卡如何组织：** 一次“远征章节”可由 3–5 个紧凑停靠点组成，每站 15–30 分钟。地图不追求巨大随机地形，而是用手工设计的地貌骨架叠加少量资源、事件和天气组合：废车场强调金属与狭窄通道，干涸水库强调水和高低差，雷暴峡谷提供高能量但会过载。每站结束从两三条路线中选择下一站，例如“更多铜但风暴更早”“可救援商队但会占用甲板空间”“绕路寻找导师留下的导航核心”，让资源决策、剧情和难度使用同一张地图推进。

**一个可想象的 20 分钟片段：** 玩家发现断裂风机里有稀有铜线，却只剩五分钟平静期。返程后把冷凝器挪到甲板外沿，为新炮塔腾出供电相邻位。风暴第二阶段改变风向，原本安全的电池开始过热；玩家穿过被箱子堵窄的通道拔下电芯，让维修臂接管炮塔，再用起重机把一块废车壳甩到怪物必经路上。风停后甲板一片狼藉，但玩家能明确说出“下次我会把电池放里面、给维修留第二条路”。这句“下次我会……”就是核心复玩信号。

**剧情与情绪：** 叙事保持轻量。主角继承了一座曾属于失踪导师的旧工坊，沿着断续无线电和维修记录追查持续扩大的风暴带。途中遇到的聚落不是长对话 NPC 城镇，而是能影响路线与设备的短事件。主线可以逐步揭示风暴来自失控的旧时代气候网络；最终选择是修复中央系统、把控制权拆分给聚落，还是让所有人迁出风暴区。核心情绪不是末日绝望，而是“外面很危险，但这台由我亲手安排的小机器正在成为家”。

优势是核心幻想和视觉传播强，能自然覆盖探索、建造、AI、战斗、资源链、天气与成长；主要风险是“探索 + 自动化 + 防守”三套系统互相稀释。垂直切片必须让每段都改变同一块甲板，不能变成三个彼此松散的小游戏。

### B. 浮岛复育师

一句话感受：**像在空中桌面上亲手把一块灰色死石养成会呼吸、会下雨、会吸引动物回家的立体花园。**

**玩家看到什么：** 一座巴掌大小的破碎浮岛悬在云海上，一半枯黄开裂，一半随着玩家行动逐渐出现溪流、草坡、花粉和小动物。镜头可以环绕少量角度，岛屿边缘直接露出岩层和根系，水滴落入云层，风向通过草、飘带和孢子清楚可见。画面的满足感来自持续的前后对比：灰色地表不是换一张贴图，而是逐步长出可参与规则的生态。

**实际怎么玩：** 玩家直接操控一名复育师或小型园丁机器人，在岛上采集种子、移动水源、修复旧设备并观察生物需求。核心不是铺满装饰物，而是建立生态关系：露水苇在迎风面产水，苔藓保湿，花群吸引云蛾，云蛾为高处果树授粉，果实又让穴兽回归并疏松土壤。机器可以帮助生态跨过初始门槛，但会占空间、耗能或制造热量；单一高效率作物可能在第一场霜雾中整体崩溃，多样性则让系统自动恢复。玩家主要“引导条件”，而不是像传统农场那样逐株重复劳动。

**关卡如何组织：** 每座岛是一个 20–40 分钟、存在多种解法的生态谜题。地形先给清晰矛盾：双峰岛的水只在低谷，断环岛的传粉路线被裂隙切断，雷鸣岛能量充足却不断烧毁幼苗。章节逐步增加生态词汇而不是只增加资源数量；上一岛救回的物种成为下一岛的新组合件。可选挑战用“限制机器数量”“保留古树”“让两种互斥生物共存”等条件制造复玩，不需要大量敌人和武器。

**一个可想象的 20 分钟片段：** 玩家先用一台旧风泵把薄雾凝成小水洼，种下耐旱苔藓后，地表开始保持湿度；荧光花开引来两只云蛾，花粉轨迹跨过峡谷，使另一侧的根桥生长并打开新区域。此时冷雾袭来，玩家之前铺成一大片的单一暖叶草迅速枯萎，只剩与岩菌共生的几株存活。玩家把风泵改为循环模式、迁移种群，十分钟后溪流重新流动，岛屿核心发光并缓慢升高。失败没有爆炸，却通过整片颜色、声音和动物行为变化让原因非常明确。

**剧情与情绪：** 玩家属于一支已经失联的“天空园丁”队伍，跟随一头受伤的小型云鲸或导航生物修复群岛。每座岛恢复后会释放一段植物年轮、旧设备录音或居民生活痕迹，逐渐揭示群岛并非自然衰败，而是过去为了维持中央城市而被抽走水与养分。结局可围绕“恢复旧中心”还是让群岛形成自治生态网展开。文本量不必大，主要让关卡本身承担叙事。

它更温暖、更适合触控与广泛受众，美术和 Shader / VFX 潜力高，范围也比 A 更容易控制；风险是玩家可能只觉得“好看、治愈”，却没有足够主动决策和重玩理由。灰盒必须证明生态组合、预测和恢复本身有趣，不能只依赖成长动画提供一次性满足。

### C. 回声遗迹

一句话感受：**像和过去的自己组成一支动作小队；每次重置都会多一名严格重演你刚才行为的队友，也可能多一个必须收拾的错误。**

**玩家看到什么：** 深蓝石质遗迹像一座破损天文钟，金色的当前角色在俯视战斗场中移动，前两轮留下的青色半透明“回声”沿旧轨迹奔跑、攻击和触发机关。攻击方向、时间轨迹与可互动机关都用极简颜色分层，画面可以在一张 GIF 里读出“一个人从三路同时进攻”，而不是堆满不可辨认的粒子。

**实际怎么玩：** 每个房间由 15–30 秒的时间段构成。玩家可以在死亡、计时结束或主动敲响回溯钟时重置房间，上一轮的移动、攻击、闪避和交互会被完整录制成回声；当前玩家再与它同时行动。第一轮也许只来得及踩住远端开关，第二轮借回声打开的门攻击盾卫，第三轮让两个回声分别牵制炮台并由本体完成处决。玩家只能保留有限数量的回声，还可花稀缺资源擦除一段错误记录，因此不是无限堆人头，而是在动作执行与时间编排之间取舍。

**关卡如何组织：** 关卡以手工房间和短分支组成，一次探索约 30–45 分钟。第一翼教“回声能触发机关”，第二翼加入只追逐回声的捕食者，第三翼加入会冻结本体但不影响旧轨迹的时间场。Boss 不靠巨量血条，而要求多轮协作：一轮引导激光切断护盾，一轮在正确时刻打断施法，最终由当前本体进入暴露窗口。少量遗物改变录制规则，例如保留最后一次攻击、让回声穿过障碍或把闪避留下伤害轨迹，从而提供构筑变化。

**一个可想象的房间：** 第一轮玩家冲向左侧开关，被盾卫挡住，只留下半条失败路线；第二轮青色回声仍会撞上盾牌，本体则故意从右侧吸引敌人转身，让旧回声意外命中背部并踩到开关。第三轮两条轨迹同时重演，门在第十一秒打开，本体穿门把时间锚钉在地上，三条攻击在同一拍汇合。玩家获得的满足不是单纯反应快，而是发现“原来刚才的失败可以变成计划的一部分”。

**剧情与情绪：** 主角是修复历史记录的“回声测绘师”，进入一座在同一分钟内反复毁灭的观测站。随着玩家重演空间，过去居民的动作残影与自己的回声重叠，逐步拼出事故真相：有人试图用回溯技术挽救城市，却把所有人困在最后一分钟。结局不需要大量过场，可以让玩家选择保存一份真实但痛苦的记录，或删除它让遗迹终于停止循环。机制天然承载关于失败、记忆和放下的主题。

它能最快验证操作、动画、战斗与特效，单局也容易收口，并且最容易做出吸引点击的短视频；风险是动作 Roguelite 竞争拥挤，精确回放、视觉降噪和敌人反应会把质量压力集中到 Game Feel。它也比 A / B 更少覆盖 Framework 的生产、资源链与长期系统能力，不能因为原型快就误认为商业风险最低。

### 6.1 三个候选的直觉差异

| 维度 | A. 游牧工坊 | B. 浮岛复育师 | C. 回声遗迹 |
|---|---|---|---|
| 玩家最先产生的欲望 | “我想把这台小破车建成能扛住风暴的家” | “我想看这块死岛在我手里活过来” | “我想看看三个自己怎样同时打赢这一间房” |
| 主要情绪曲线 | 安心准备 → 风暴压迫 → 劫后余生 | 好奇试种 → 系统生长 → 修复与治愈 | 失败困惑 → 理解规律 → 精确合奏 |
| 最核心的乐趣 | 空间布局被真实压力验证 | 生态组合与强烈前后变化 | 与过去行为协作的动作编排 |
| 内容压力 | 中高：设备、探索、威胁三类内容 | 中：物种与地形必须产生足够组合 | 中高：动画、敌人、房间和手感都要精确 |
| 最容易做出的传播素材 | 风暴前后同一甲板的变化 | 灰岛到繁盛生态的延时变化 | 多个回声同时完成连击的短 GIF |
| 目前最需要证明 | 三段循环是否真是同一件事 | 没有传统战斗是否仍有张力与复玩 | 独特机制能否压过动作 Roguelite 的拥挤感 |

### 6.2 暂不最终锁定的原因

A 与 B 可以共用一个低成本技术灰盒：移动、拾取、在有限网格摆放功能件、启动环境压力、观察系统结果。先用两套概念卡和同一灰盒回答“危险迁徙”还是“生态复育”更能激发玩家欲望，避免为三个概念分别开发三款游戏。

## 7. 《游牧工坊》最小产品定义

### 7.1 核心循环

```text
选择停靠点
  → 离开工坊探索并回收
  → 在有限甲板上布置生产、供能和防御
  → 风暴来临，布局接受压力测试
  → 修复、取舍、解锁蓝图并迁徙
  → 在下一站面对新的资源与规则组合
```

关键设计要求：探索获得的东西必须改变甲板决策；甲板决策必须在风暴中产生肉眼可见的后果；失败必须提供可理解的信息，而不是只让数值归零。

### 7.2 垂直切片范围盒

目标是交付一段 **20–30 分钟、可以从标题玩到结算、愿意让陌生玩家试玩** 的内容：

| 内容 | 首个切片上限 |
|---|---|
| 世界 | 1 个生物群系、1 个工坊甲板、少量手工组合的探索节点 |
| 玩家 | 1 个可直接操控角色，键鼠和手柄；可选 1 个工具无人机 |
| 资源与设备 | 约 6 种资源、4 种生产 / 供能设备、3 种防御或应急设施 |
| 威胁 | 3 种敌人 / 环境威胁 + 1 次有阶段变化的风暴事件 |
| 成长 | 少量蓝图选择；优先新组合，不堆永久属性数值 |
| 表现 | 一套明确 Art Direction、昼夜 / 风暴、关键交互动画、代表性 Shader / VFX / 音频 |
| 产品闭环 | 标题、设置、教程、暂停、存档 / 恢复、结算、失败重试、Windows 可执行包 |

切片不得依赖第二生物群系、复杂剧情、随机大地图或几十种设备才能“开始好玩”。若没有这些内容就无法成立，应重做循环而不是扩产能。

### 7.3 视觉与镜头建议

- 风格化低至中等复杂度 3D，强调大轮廓、材质分区和可读动画，不追求写实微表面；
- 斜俯视固定范围镜头，可有限旋转或四向吸附；先避免自由第三人称镜头带来的动画、遮挡和关卡成本；
- 工坊采用微缩模型 / 桌面景观感，危险天气形成强烈色温与明暗反差；
- URP 为当前渲染基线，首批只做能重复服务状态表达的 Shader / VFX，不以特效数量衡量完成度。

## 8. 证据 Gate：从想法到正式生产

### Gate 0：概念值得点开

产物：A / B 各一张概念卡、一句商店短描述、一个 10–15 秒 Gameplay Storyboard、3–5 个真实竞品页面拆解。

通过信号：目标玩家能在十秒内复述“我做什么、为什么有趣、与熟悉游戏哪里不同”；A 或 B 在不解释 Framework 和 AI 的情况下仍有人主动想玩。若两者都不能，先改幻想，不进入美术生产。

### Gate 1：灰盒值得再玩一轮

产物：10–15 分钟 Unity 灰盒，至少包含移动 / 交互、拾取、网格摆放、资源转化和一次压力事件。

通过信号：玩家能自行完成一轮；失败后知道下一轮想改什么；探索、布局与压力事件没有任何一段被普遍视为多余。先测 5 名目标玩家，再决定扩展。

### Gate 2：资产管线与风格能持续

产物：一个英雄级工坊模块、一个角色或敌人、一个环境模块族、一个材质族、一组关键 VFX / SFX，并全部进入真实场景。

通过信号：风格在游戏镜头下统一；拓扑、UV、碰撞、LOD、动画、材质、命名和授权可追溯；修改一轮的成本可接受；代表性目标机达到临时帧率与内存预算。

### Gate 3：垂直切片是一个产品

产物：上述 20–30 分钟完整切片、Windows 包、基础分析事件、试玩观察记录、截图与短视频素材。

通过信号：陌生玩家无需开发者在旁指导即可完成；多数核心缺陷来自可修的平衡和表达，而不是“不知道为什么要玩”；构建、存档、输入、视觉和性能有可复核证据。

### Gate 4：商业表达成立

产物：Steamworks 账号与 App、通过审核的 Coming Soon 页面、真实 Gameplay Trailer / GIF、Demo 或 Playtest、清晰标签和语言计划。

通过信号：商店页面能持续产生高质量外部反馈和愿望单；Demo 数据与访谈支持继续生产。是否参加某届 Next Fest 要倒排准备，且每款游戏只能参加一次，不能把第一次可运行版本仓促消耗掉。

### Gate 5：内容生产与发行

只有 Gate 0–4 的证据支持，才扩展生物群系、敌人、设备、剧情与平台。排期以可玩的里程碑和内容吞吐量为依据，不先写一个远期发布日期再倒逼质量。

## 9. AI、生成资产与 Harness 的生产方式

### 9.1 AI 的位置

AI 用来加速搜索、比较、草图、变体、代码、测试、重复操作和证据整理；Art Direction、最终资产选择、玩法取舍、玩家反馈解释、商业授权和发行责任仍由人承担。

建议流水线：

```text
玩家目标 / 产品假设
  → 可审查的设计或资产 Brief
  → 人工、生成工具或混合制作
  → DCC / Unity 规范化
  → 运行时、视觉、性能与授权验收
  → 真实玩家反馈
  → 保留、返工或删除
```

候选工具沿用 [AI 游戏开发能力图谱](ai-game-development-capability-map.md) 的渐进策略：概念图可先使用 Codex ImageGen；Blender 作为 3D 资产的候选权威 DCC；Meshy 只在拓扑、UV、商业授权和重复质量通过资产 Spike 后采用；Shader Graph / VFX Graph 与 Material Maker 候选服务代表性效果；音效和音乐先按 [AI 音乐与音效生产候选](ai-audio-production-research.md) 对照 Stable Audio 3、ElevenLabs、AIVA 等少量方案，所有结果仍经 DAW、Unity 和授权台账验收。探索阶段不急于写安装指南或绑定平台 Skill。

### 9.2 生成资产台账

任何会随游戏发布、且使用生成式 AI 制作或实质改造的图片、模型、纹理、音频、文本或本地化，至少记录：

- 资产 ID、最终路径和用途；
- 工具 / 服务、模型或版本、生成日期；
- Prompt、Seed、输入参考和参考素材权利；
- 服务条款 / 许可证快照或链接、付费账号归属；
- 人工修改、复核人、替换历史；
- 是否属于 Steam 内容调查中的预生成或运行时生成内容。

Steam 官方要求披露玩家会消费的生成式 AI 内容，并要求产品不包含非法或侵权内容。项目因此默认只使用**预生成、可人工审查、可替换**的内容；运行时生成不是首款游戏需求。

### 9.3 游戏级 Harness

SSFramework 现有 Harness 提供执行与证据骨架，新游戏逐步补自己的 Oracle：

| 层 | 首批证据 |
|---|---|
| 规则与经济 | 固定 Seed、资源守恒、结算与失败边界的 EditMode 测试 |
| 玩家路径 | 真实 Input Action 驱动的“标题 → 一轮 → 结算 / 重试”PlayMode smoke |
| 视觉 | 固定镜头、天气和 UI 状态截图；人工批准少量黄金基线 |
| 性能 | 固定 Player Build、设备与采样窗口下的 CPU / GPU / GC / 内存预算 |
| 构建 | Windows 可分发 Player 包、启动 / 存档 / 退出 smoke；后续平台各自独立证据 |
| 体验 | 观察玩家、访谈、回放与问题严重度；自动测试不能替代这一层 |

Harness 的目的不是让 Agent 自己宣布“游戏好玩”，而是让每次迭代能稳定运行、暴露状态、按既定标准判断、失败后恢复，并把证据交给人和玩家作更高层决策。

## 10. 仓库与 Framework 边界

正式建项时使用暂定目录（最终产品名确定后再一次性命名）：

```text
Assets/Game/NomadWorkshop/
├── Runtime/          # 玩法、表现与组合根
├── Editor/           # 只服务本游戏的生产工具
├── Tests/EditMode/
├── Tests/PlayMode/
├── Content/          # Prefab、材质、动画、音频等 Unity 资产
└── Settings/         # 本游戏 Profile 与配置
```

- 游戏拥有独立 asmdef，只消费 Framework 公共 API，不复制 Framework 源码；
- 只服务本游戏的玩法、敌人、设备、关卡、UI 和 Art Pipeline 留在游戏目录；
- 只有第二次出现、跨游戏成立，或确实阻断 Framework 公共用法的缺口才回流；
- 回流时按风险决定 Interface、测试、Demo、guide 或 ADR，不机械凑形式；
- 商业游戏的产品文档在方向确认后可下沉到游戏目录，本文继续保留平台与立项决策摘要。

## 11. 主要风险与提前终止信号

| 风险 | 提前信号 | 应对 |
|---|---|---|
| 三套玩法互相稀释 | 玩家普遍跳过探索、生产或防守中的一段 | 删除或合并最弱环节，不先补内容 |
| “紧凑沙盒”被理解为无限内容 | 玩家只问大地图、联机和无限建造 | 商店表达明确单局与微缩范围；强化组合深度而非面积 |
| AI 资产风格泛化 | 单件好看，放进同一镜头却像多个游戏 | 先做 Art Bible 与模块族；英雄资产人工精修；不合格资产可替换 |
| 3D 产能失控 | 一个普通模块也需多天手工救拓扑 / UV / Rig | 降低风格复杂度，重做模块化规范，停止不稳定生成链 |
| Framework 反客为主 | 里程碑以新公共模块数量而非玩家结果汇报 | 游戏侧先解问题；达到回流证据再抽象 |
| 过早多平台 | PC 核心循环未成立却开始做触控和商店 SDK | 移动工作必须经过 Gate，不以“以后可能需要”进入 Now |
| 太晚面对市场 | 完成大量内容后才发现一句话和视频无法解释 | Gate 0 就做 Capsule / Storyboard，Gate 3 前开始外部试玩 |

## 12. 下一批实际工作

1. 把 A《游牧工坊》、B《浮岛复育师》和 C《回声遗迹》的同质量假想 Gameplay Frame 与一句话承诺组成无 Framework / AI 说明的概念卡，做并排盲测；只迭代玩家没有读懂的玩法关系，不把概念图当作最终美术承诺。
2. 建立 15–25 个可比游戏的小型表格，记录核心幻想、镜头、核心循环、价格、评价量、发行时间、团队与可见差评主题；数据标明官方事实或第三方估算。
3. 用共享规则搭一个无正式资产的 Unity 灰盒：移动、拾取、有限网格摆放、资源转化、压力事件、结算。
4. 招募第一轮 5 名目标玩家，统一记录“点击欲望、理解、卡点、主动重玩理由”，不只问“喜不喜欢”。
5. 依据证据确认 A / B / C / 新方向，再确定正式产品名、预算上限、预计团队投入和首个里程碑。

下一轮最值得由用户参与的三个产品判断是：整体情绪更偏“温暖机械家园 + 风暴压迫”还是“纯治愈复育”；玩家是否直接操控一个角色；永久成长更偏新蓝图与知识，还是明显数值强化。当前推荐分别是前者、直接操控、以新组合为主。
