# ADR-0032：Outpost M8 —— 残骸实体化 + 推挤入模拟（让后端差距随战局拉大）

**Status:** Accepted（2026-07-12）

## Context

用户在 M7（ADR-0031）后观察到一个真问题：**设置窗切 Ecs/Reference 后端，帧率差不够明显**。归因三条：

1. **平台期把敌人数/在飞弹数封顶** → Reference 的模拟耗时钉在 ~14ms 不再随时间恶化，差距是"恒定的一段"而非"越打越大"；
2. **渲染/特效/编辑器开销是两后端共享成本** → 稀释了那 9ms 的模拟差；
3. **编辑器 job 安检抽走 ECS ~30% 优势**（ADR-0030 已记）。

用户的洞察指向解法：**残骸是全场唯一"累计增长"的量**（模拟侧上限 2 万→3 万具，随每次击杀单调爬到上限）。若把 M7 的表现层推挤（预算限流的 cosmetic）扶正为**模拟规则**，其演算量 `O(残骸 × 邻域敌人)` 随残骸累积增长——Reference 后端随战局推进**逐波变慢**、ECS 并行 job 摊平，后端差距第一次"随时间拉大"而非恒定。

这直接推翻 ADR-0031 §5「推挤进模拟：真物理推挤成本高一个数量级、对规则无益——推挤是纯表现」的结论。M7 时它只是"成本高、对规则无益"所以不做；M8 把那"高一个数量级的成本"**正是当作目标**（它就是后端差距的放大器），并给它规则意义：**密度记账跟随残骸位置**——敌人海犁开残骸，车辙被真的踩穿、残骸往路两侧堆成垄，防御地形随进攻路径侵蚀。定位：**规则级里程碑**——Sim 契约演进（残骸从密度计数升为逐实体状态）、两后端同规格实现、表现层从"独立烘焙"简化为"模拟槽位镜像"。

## Decision

### 残骸成为逐实体模拟状态（进 Sim 契约，两后端同规格）

| 决策 | 内容 | 为什么 |
|---|---|---|
| 残骸 = 环形槽位实体 | 每具残骸持有 `Pos`（当前位置）/`ArchIndex`/`Drift`（累计漂移）/`Seq`（创建序号）/`Cell`（当前密度格）。M7 的"只存格号环形缓冲"升级为 SoA 数组 | 位置成为可变模拟状态是推挤的前提；密度格计数从"落定即定"变为"跟随位置迁移" |
| 确定性静置散布 | 落点 = 事件点 + `SimMath.WreckRestOffset`：沿远离哨站径向滑出 + 侧向抖动，幅度系数由 `SimMath.Hash01(seq)` **整数哈希**取 | **零三角函数、零 RNG 流消耗**——sqrt 是 IEEE 正确舍入、整数哈希两后端逐位一致，且不动现有 RNG 消耗顺序契约（M7 的"表现层随机滑出"上移为模拟规则时必须去随机源） |
| 推挤 = 每 tick 相位 | 每具残骸找**重叠的最近敌人**（距离平方最小、平票取小实例 id），沿"敌→残骸"推 `min(重叠量, PushSpeed×dt, 剩余漂移预算)`；跨密度格时旧格 −1 新格 +1 | 最近+id 平票是**顺序无关的归约**：结果与遍历顺序无关 → 两后端可逐位对拍、ECS 可逐槽并行。密度记账跟随位置 = 车辙被踩穿（规则意义，非纯观感） |
| 车辙回淤 | 漂移预算按 `DriftRecoverPerSecond` 随时间恢复（≤0=一次性耗尽即定格） | 车流必须持续碾压才能保持通道，停止通行的车辙重新淤积；也让推挤负载**在成熟战场持续存在**（不回淤则漂移到顶的残骸只剩一次早退比较，负载饱和后回落 → 后端差距又变恒定） |
| 敌人占位网格 | 每 tick 重建（计数→前缀和→填充的 **CSR 三段式**，确定性）；格边长 = `max(1, 最大敌半径×(1+WreckBodyScale))`，3×3 邻域必覆盖一切接触对 | 推挤查询"残骸身旁的敌人"，均匀格 + CSR 是最便宜且无浮点分支的确定性空间索引；格边长按最大接触距离推导（不能复用密度格，接触上限 >1.0） |
| 残骸槽位只读访问器 | `int WreckSlotCount` + `WreckSnapshot GetWreckSlot(int)`（Seq+ArchetypeId+Position，稳定槽位地址） | 表现层增量镜像的读源：`Seq` 变=槽位环形换血、`Position` 变=被犁动 |

### 表现层从"独立烘焙"简化为"模拟槽位镜像"（纯表现，零对拍影响）

| 变更 | 实现 | 收益 |
|---|---|---|
| 退役表现层推挤通道 | 删 `SwarmRenderer` 的 `_pushGrid`/`PushWrecksByEnemies`/扫描预算/轮转游标/表现残骸网格全套（M7 引入） | 推挤只有一处实现（模拟侧），表现层不再自算一遍——同 M7 删音频延迟机制的简化故事 |
| 残骸层改镜像 | `SyncWrecks(sim)` 逐槽比对缓存 `Seq`/`Pos`：Seq 变=换血（旧居民 swap-remove 出批次、新残骸入批 + 起原地落定动画）、Pos 变=被犁动（原位重写矩阵 + 槽位奇偶滚转扰动） | 矩阵/颜色只在变化时写、每帧直接提交缓存数组；无头快进的战场历史由镜像**自动发现**——`SpawnWreck`/`BakeWreckInstant`/快进烘焙钩子全删 |
| 落定动画 | 原地收缩/滚转/余烬冷却 0.55s（滑出已由模拟侧散布偏移承担，不再表现层滑出） | 动画与模拟位置解耦，Seq 失配即作废（槽位被复写时旧动画自动丢弃） |

### 配置（新增三个 `battleglobal` 旋钮）

`wreckPushSpeed`（推挤速度，≤0=关闭）、`wreckPushMaxDrift`（累计漂移上限，可跨密度格）、`wreckPushDriftRecover`（回淤速度）；`wreckSimCap` 2 万→3 万（残骸上限提高，战场更密、推挤负载更足）。改这四个 json + 重生成即调。

## 验证结果

### 对拍两级（M6/M7 方法论复用 + 加"逐槽残骸位置"维度）

- **逻辑级（关 Burst，job 走 Mono）**：贪心升级 lockstep 12 波 5447 tick **逐 tick 逐位全等**——聚合值 + 炮塔角 + **每一具残骸的 Seq/位置逐位相等** + 泥地密度网格逐格计数全等。残骸实体化 + 推挤 + 回淤三条改动移植零逻辑偏差。
- **规格级（开 Burst）**：seed 777 贪心 18 波，两后端每波击杀/得分/清波 tick/残骸数**完全相等**（本 run 未在 18 波内触发 ulp 分叉——推挤的"最近+id 平票"归约对浮点比 M7 溅射归属更稳）；更深波次预期仍会像 M7 那样在某个 ulp 边界分叉成 <1% 归属漂移，量级不变。

### 性能（Windows 编辑器，Ecs 开 Burst / Reference 纯托管，同机同 seed）

| 点位 | 残骸数 | 敌人峰 | Reference | Ecs | 倍率 |
|---|---|---|---|---|---|
| **成长期**（w12） | ~560 | — | avg **0.23ms** / p95 0.42 | avg **0.25ms** / p95 0.36 | **≈1×（持平）** |
| **平台期**（w24） | ~20450 | ~2250 | avg **13.8ms** / p95 25.8 / max 30.4 | avg **3.25ms** / p95 5.65 / max 6.5 | **~4.3×** |

**这是与 M7 的关键差别**：M7 的后端差距在平台期是恒定的一段（~2.6×）；M8 让差距**随残骸累积拉大**——w12 两后端几乎持平（都 ~0.25ms，推挤负载尚未累积），w24 残骸满 2 万时 Reference 已 13.8ms（叠渲染破 60fps）、Ecs 仍 3.25ms。隔离实验（Reference w27 满 2 万残骸）：关推挤 avg 6.6ms、开推挤 avg 9.7ms——推挤相位单独贡献 ~3ms（Reference 单线程），正是随残骸增长、被 ECS 并行 job 摊平的那部分。**"越往后打，切 OOP 越卡、切 Ecs 越稳"的时间维度收益达成。**

### 平衡

无头 ECS 托管 40 波长跑（seed 424242）：**w40 存活**，成长期（w1-24）每波 100% 血通过，平台期（w25+）单波最低血 72~83%（每波消耗 ~17~28%）。残骸减速让敌人变慢、对防御是净帮助，故消耗略低于 M7——这是主题正确的（泥地拖慢进攻者），且推挤"踩穿车辙"让减速随进攻路径自我削弱，形成自平衡张力，未激进重调。

### Play 冒烟（编辑器，两后端各一局）

- **Ecs**：托管 4× 快进到 w14（913 击杀、973 残骸），热力图叠加清晰、残骸犁开动画正常、HUD 性能行 `Ecs · 敌 93 · 残骸 973 · 模拟 0.19ms · 168fps`，切 0.5× 慢放看清推挤。
- **Reference**：撤离切后端后新开一局，w10（254 残骸）渲染路径完全一致（`SwarmRenderer` 后端无关，经 `IBattleSim` 接口读）、热力图呈现哨站周围残骸堆积（"漏怪从哪来"的可视化）、`Reference · 模拟 0.02ms`。
- 全程零报错、停 Play 零报错；PlayMode 测试套 **325/325 全绿**（框架无改动，回归确认）。

## 明确不做

- **ECS 侧空间网格加速弹丸碰撞**：保持同算法对比的干净归因（同 M7）。
- **残骸挡子弹/挡敌人移动**：后期自家尸堆挡弹/挡路是负体验；推挤只让残骸被推开、不反向阻碍敌人移动（敌人移动仍只受密度减速）。
- **残骸物理堆叠/相互碰撞**：残骸之间不互相推挤（只被敌人推），避免 O(残骸²) 的真物理成本——推挤的负载增长来自"残骸×邻域敌人"已够放大后端差距。
- **局中后端热切**：M6 已拍板（模拟一次性实例，状态迁移含 RNG 内部态与残骸 SoA 不值得为演示开关加接缝）。

## Consequences

- 后端置换的收益从"平台期恒定 2.6×"升级为"**随战局拉大**"——切片最想传达的"选对执行模型，规模越大越值"有了时间维度的直观证明。
- ADR-0031 §5 的"推挤是纯表现"被本 ADR 反转（同 M7 反转 ADR-0030 §4 的模式）：一个决策的"不做"理由（成本高一个数量级）在下一个里程碑可能正是"要做"的理由（那成本就是要演示的东西）——记录反转链让后来者看清判断随目标演进。
- 表现层净简化：删掉 M7 的整套表现层推挤通道，残骸层从"独立烘焙 + 快进专用烘焙钩子"收敛为单一的"模拟槽位镜像"——规则搬进模拟后，表现层只需照着画。
- `SimMath.Hash01` + `WreckRestOffset`（整数哈希驱动的确定性散布）沉淀为"需要确定性伪随机但不能动 RNG 消耗顺序"的可复用样本。
- 对拍两级方法论再加"逐槽实体位置比对"维度，并首次验证"最近+id 平票"这类顺序无关归约对逐槽并行的对拍友好性。
