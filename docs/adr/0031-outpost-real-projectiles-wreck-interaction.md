# ADR-0031：Outpost M7 —— 真弹道碰撞 + 残骸互动（让 DOTS 优势在真实游玩中可见）

**Status:** Accepted（2026-07-12）

## Context

M6（ADR-0030）证明了后端可置换与 Burst 的规模收益，但留下一个诚实的结论：**真实游戏规模下两个后端都远离帧预算**（平台期 0.38 vs 0.52ms），差距只在 4 万敌的合成基准里可见。用户提出把真实玩法本身推进那个量级，并让玩家在设置窗切后端时**肉眼看到帧率差**——三件事：

1. **真弹道**：hitscan（逐 tick 炮口锥内选敌、伤害击发帧结算）改为**飞行弹 + 真碰撞检测**——弹×敌配对数随射速与敌人数自然增长，从每 tick 几百涨到十万百万级；
2. **子弹飞很远才消失**：未命中的弹飞出场外才消散，是在飞弹数量的直接倍增器；
3. **残骸互动**：残骸首次获得模拟意义（减速泥地）+ 敌人推开残骸的物理观感（纯表现）。

这直接推翻了 ADR-0030 §4「尸堆减速场为压测加规则不值当、放弃」的结论——M6 时它只是压测候选；M7 把它扶正成**规则本体**（残骸密度即防御地形），压测收益是副产品。定位：**规则级里程碑**——Sim 契约演进、两后端同规格实现、平衡重标定、表现层三个新系统。

设计红线：Reference 保持「直白 OOP、无空间分区」的对比基线身份——后期在飞弹×敌人海把它推向帧预算**正是演示本体**；ECS 侧刻意也不加空间网格，保持「同算法、不同执行模型」的干净归因（若数字显示 Burst 也吃紧，那是"下一课"的素材，不在本里程碑）。

## Decision

### 规则（进 Sim 契约，两后端同规格）

| 决策 | 内容 | 为什么 |
|---|---|---|
| 真弹道 | 击发逻辑不变（转向最近敌、对准锥容差才击发、火墙转向途中也击发、`MaxShotsPerTick`）；每发生成一颗弹丸沿炮口方向**直飞不追踪**。火墙加 ±2° 确定性散布（消耗种子 RNG，双后端同序）；点射无散布 | 命中交给物理后，"能不能打中"从击发帧的锥判定变成弹道的涌现结果（穿排、扫掠漏射都自然发生） |
| 扫掠碰撞 | 命中 = **线段 vs 圆**（弹丸本 tick 位移段与敌圆求交，取最早交点）——弹速 0.8u/tick 远大于炮灰半径，逐点判定会隧穿 | 隧穿是快弹×小目标的必然 bug，扫掠是唯一正确解；`SimMath.SegmentCircleHitT` 标量入参、两后端同式 |
| 事件时序 | `TurretFired` 仍在击发帧（炮口闪光/热度源）但**删 `Aim`/`Hit` 字段**（弹丸命运由物理决定）；`EnemyHit` 改在**弹着帧**触发、位置=弹着点 | 弹着音效/特效因此天然同帧同点——M6 的「音频弹着对拍」人工延迟机制（`ScheduleSfx`/`FlushPendingSfx`/`FlightDelay`/`TracerFlightSpeed`）**整套删除**（真弹道让它变多余，简化） |
| 残骸减速泥地 | **密度网格**（两后端 O(1) 同实现、天然确定性，是规则不是优化）：场地按 `WreckCellSize=1` 划格，击杀/自爆令所在 cell 计数 +1，环形上限 `WreckSimCap` 复写；敌人移速 ×= `max(SlowFloor, 1−SlowPerCount×cell计数)` | "上一波死在哪，下一波就在哪儿减速"——残骸从纯观赏变成防御地形。均匀密度格而非四叉树：查询模式固定是"点采样密度"，均匀格最便宜且无浮点比较分支（两后端可逐位一致） |
| 弹丸快照 | `int ProjectileCount` + `ProjectileSnapshot GetProjectile(int)`（Position+Direction，O(1)，索引不稳定，与 GetEnemy 同语义） | 表现层实例化绘制的读源 |
| 泥地网格只读访问器 | `WreckGridInfo WreckGrid` + `int GetWreckCellCount(int)`（Dim/CellSize/Half + 逐格计数，O(1)） | 泥地热力图可视化直读模拟侧密度格；规则的可视化而非另算一套 |

### 表现层（纯表现，零对拍影响）

| 系统 | 实现 | 纪律 |
|---|---|---|
| 弹丸绘制 | `SwarmRenderer.DrawProjectiles`：拖尾菱形 mesh 按飞行方向定向、HDR 青白（Bloom 光痕）、1023 分批——与敌人海同套实例化姿势 | 真弹道下同屏数百上千，逐弹 GameObject 不可行 |
| 残骸推挤 | 存活敌人拱开身旁已烘焙残骸：表现残骸网格邻格查询 + **原位重写已烘焙矩阵**（矩阵本就常驻数组，改写≠重建）；单具**累计漂移上限 0.8u**（< 模拟格边长 1.0，表现位移不动摇模拟侧记账格位）；**每帧「检视残骸」扫描预算封顶**（成本在逐具距离判定，成熟战场大量残骸已到漂移上限只被判定不被推——预算按检视数扣才真正封顶最坏扫描，不是按实际拱动数） | 拱动只让路不清道；漂移上限保证"看见尸堆=看见减速区"的直觉不被表现破坏 |
| 泥地热力图 | 读模拟侧密度格绘制半透明色块（√ 曲线抬低密度可见性，亮度饱和点=减速到下限所需密度——热力图刻度即减速刻度）；设置窗开关即时生效 | "残骸是防御地形"这条规则的直读可视化，默认关（教学/调试视图不打扰常规游玩） |

## 验证结果

### 对拍两级（M6 方法论复用，同 Setup+seed+Tick 序列）

- **逻辑级（关 Burst，job 走 Mono）**：12 波 5437 tick 贪心升级全程**逐 tick 逐位全等**（击杀/得分/敌数/在飞弹数/血量/炮塔角全部逐位相等，**含泥地密度网格逐格计数全等**）——真弹道+泥地两条新规则移植零逻辑偏差。
- **规格级（开 Burst）**：前 5 波每波击杀/得分/清波 tick 完全相等；w6 起一次**溅射击杀归属**在 ulp 分叉处易主（得分差 5，击杀数仍相等），此后每波击杀数完全相等、得分固定差 5~10、清波 tick 漂移 ≤1（个别 ≤16）。真弹道把分叉从 M6 的 w22 提前到 w6（弹道对浮点更敏感），但**归属漂移量级不变**——仍是「同一个游戏、不是逐位同一局」，印证 M6 的跨编译域浮点边界结论。

### 性能（Windows 编辑器，Ecs 开 Burst / Reference 纯托管，同机同负载）

| 负载 | Reference | Ecs | 倍率 |
|---|---|---|---|
| **真实平台期**（w23-24，~2920 敌 + 290 在飞弹） | avg 6.48ms / p95 **14.2ms** / max 19ms | avg **2.46ms** / p95 5.27ms | ~2.6× |
| **合成压力**（慢弹 8u/s×80 消散半径，~1500 敌 + **1623 在飞弹**） | avg **39.2ms** / p95 67ms / max 76ms | avg **12.0ms** / p95 21ms | ~3.3× |

结论：真弹道把真实平台期从 M6 的 0.5ms 量级推到 Reference **p95 14ms**（叠加渲染即破 60fps 帧预算）——**"切 OOP 后期肉眼可见掉帧、切回 Ecs 恢复满帧"的验收目标达成，且用真实玩法而非合成基准**。合成压力（千级在飞弹）下 Reference 崩到 ~15-25fps、Ecs 仍近可玩。两后端 O(P×N) 同算法，差距纯来自 Burst 编译 + 连续内存 + 并行移动。

### 平衡重标定

无头 harness 托管 60 波长跑（雷达优先贪心）：**60 波不死**，平台期敌峰稳定 ~3700，单波最低血从成长期 100% 渐降到 w42+ 的 63~77%（每波消耗约 30~35%，托管最优打法留出余量、真人会更险）。真弹道引入 DPS 交付延迟（弹飞行 ~0.3s）与穿排收益（弹打穿先死目标后继续命中同线后敌），标定只动 `waverole.json`（炮灰 `maxCount` 3800→4500、突袭机 120→150）补偿弹道延迟带来的漏怪。

### Play 冒烟（编辑器，Ecs 后端）

启动→标题→战斗，托管快进到平台期（w28、3.4 万击杀、2971 敌、残骸烘焙至 3 万上限）：弹丸渲染为青色辐射光痕（HUD 性能行新增「弹」计数实时刷新）、泥地热力图正确叠加（外圈死亡带最亮）、开关即时生效、sim 1.26ms（Ecs 后端在 3000 敌下仍 <2ms）、全程零 M7 相关异常。PlayMode 测试套 **325/325 全绿**（框架无改动，回归确认）。

> Play 冒烟中发现并修复：推挤通道原按「实际拱动数」扣预算，成熟战场残骸多已到漂移上限（只被判定不被推、`continue` 不扣预算）→ 最坏情况扫遍全部敌人×邻格残骸（~80 万次/帧）无界。改为按「检视残骸数」扣预算（8000 次距离判定/帧封顶），成本恒定可控。

## 明确不做

- **ECS 侧空间网格加速弹丸碰撞**：保持同算法对比的干净归因。数字显示 Burst 尚有一个数量级余量（合成压力 12ms vs 帧预算），未到吃紧，加分区是"下一课"素材。
- **残骸挡子弹**：后期自家尸堆挡弹是负体验。
- **穿透弹/跳弹参数化**：emergent 穿排（弹打穿先死目标继续命中）已够，不加专门参数（不过度设计）。
- **推挤进模拟**：真物理推挤成本高一个数量级、对规则无益——推挤是纯表现，零对拍影响。
- **局中后端热切**：M6 已拍板（模拟是一次性实例，状态迁移含 RNG 内部态不值得为演示开关加接缝）。

## Consequences

- 垂直切片的核心卖点从「后端可置换」升级到「后端置换**有真实可感的收益**」——设置窗切 OOP，平台期后期肉眼掉帧；切回 Ecs 满帧。这是接缝价值的最直观证明。
- 泥地密度网格成为「规则用均匀格表述、天然确定性、两后端 O(1) 同实现」的教学样本（对比四叉树/AABB 的适用边界）。
- 真弹道简化了音频层：M6 的弹着对拍延迟机制整套删除——真实事件时序让音画天然同帧，"为对拍加的人工延迟"随规则演进变多余。
- 对拍两级方法论（关 Burst 锁逻辑、开 Burst 验规格）再次复用并加了「密度网格逐格比对」维度，continue 沉淀于 outpost-tech-notes。
